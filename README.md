### WordPress core

I contribute through the **Test Team** during the 7.1 cycle — patch testing, bug reproduction, and tracing regressions back to the changeset that caused them.

**Two props on committed changesets:**

| Changeset | Component | What I did |
| :--- | :--- | :--- |
| [**[62854]**](https://core.trac.wordpress.org/changeset/62854) | Filesystem API | Verified the permissions comparison in `WP_Filesystem_Direct::chmod()`. The commit also added a regression test to the suite. |
| [**[62865]**](https://core.trac.wordpress.org/changeset/62865) | Login &amp; Registration | First trunk test of the focus-colour fix. |

> Both came from **testing other people's patches**, not from writing my own code. I think that says something useful about how accessible core testing actually is.

**Also on the public record:**

- [**#65697**](https://core.trac.wordpress.org/ticket/65697) — Media Library filter bar regression. Traced to the exact 7.0 changeset. I'm the only tester on the fix milestoned for 7.1.
- [**#64921**](https://core.trac.wordpress.org/ticket/64921) — a REST API failure nobody had reproduced in four months. Built an mu-plugin simulation, confirmed a hard 400, and showed the proposed patch didn't fix it. Another tester later used the same technique and credited it.
- First-tester reports on **#64729**, **#65491**, **#65658**, **#65696**, **#65605** and more.

Always with evidence — DevTools traces, before/after screenshots, PHPUnit runs. Never *"works for me."*
